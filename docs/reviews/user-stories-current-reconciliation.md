## Findings

### C-01 — Resolved: contributor setup and CI have supporting design

Original finding (Medium): Requirements: stories L24–47, US-31 and US-32. Design: §8 installation L454–489 and §9 execution L663–676 describe user-project setup and lockfiles; §12 L868–923 lists product tests. These supply only fragments of contributor setup. No contributor bootstrap, shared verification command contract, clean-checkout setup validation, CI triggers, locked installation procedure, or failure/log reporting is described. Consequence: Milestone 0 lacks a design for its local and automated verification outcomes.

Original proposed correction: design §§8–10 and §12. Add a contributor-environment subsection specifying supported-version/tool documentation, harness checkout and locked `uv` synchronization, local CLI execution, shared test/lint/format/type/smoke commands, configuration/credential handling, and a clean-checkout setup fixture. Add CI behavior for pull requests/default-branch updates, frozen lockfile installation, those same commands, and visible failing results/logs. Add all US-31/32 criteria to traceability. Exact tool/version choices can remain implementation decisions.

Scoped reconciliation: A focused review against the current US-31-AC-01–10 and US-32-AC-01–04 confirms supporting design in §8, “Contributor development and package verification (Milestone 0),” complete criterion links in §10, and Milestone 0 delivery and exit criteria in §11. Developer-approved clarifications make rule-suppression and check-exclusion guidance, recorded exception justifications, macOS clean-checkout verification evidence, and failing CI results with pull-request-accessible logs explicit. Contributor setup, locked dependency synchronization, source-checkout CLI execution, shared local/CI checks, and configuration/credential guidance are covered. This resolves the documentation gap; implementation and successful verification remain separate work. The original finding, criterion matrix, and counts below are retained as historical baseline evidence, not current coverage results. C-02–C-05 were not reassessed in this focused review.

### C-02 — Resolved: distributable package verification is specified

Original finding (Medium): Requirements: stories L49–59, US-33. Design §8 L487 requires a build system, CLI and packaged resources; §10 L843 requires separate-project installation fixtures. Neither specifies both distribution formats, wheel installation outside the checkout without development dependencies, rebuilding from the source distribution, or CI execution of these checks. Consequence: Git installation fixtures could pass while a distributable omits resources or source files.

Original proposed correction: design §§8–10. Add the following: “Build wheel and source distributions using a documented local command. Install the wheel with only declared runtime dependencies into a clean environment and execute checks outside the source checkout. Verify `agent-ml`, `agentic_ml`, initialization templates, and runtime guidance. Build a wheel from the source distribution and repeat the same checks. Run these commands in CI with visible results and diagnostic logs.” Add US-33 traceability.

Scoped reconciliation: A subsequent focused review at Git revision `2f26c02e1620d132bbe9bf38969d7790675403ef` against the current US-33-AC-01–07 confirms supporting design in §8, “Contributor development and package verification (Milestone 0),” complete criterion links in §10, and package-verification deliverables and exit criteria in §11. The design specifies wheel and source-distribution builds; clean-environment installation with declared runtime dependencies; checks outside the checkout without editable installation or development dependencies; and the same installed-package checks for directly built wheels and wheels rebuilt from the source distribution. Checks cover `agent-ml --version`, successful exit and version agreement with distribution metadata, `agentic_ml` imports, and reading provisional template and runtime guidance contents against expected values through each installed wheel. Source-checkout smoke verification, documented local reproduction, CI execution, failing results, and diagnostic logs are also covered. No user-story or design changes were needed. Implementation and successful verification remain separate work. The original finding, criterion matrix, and counts below remain historical baseline evidence. C-03–C-05 were not reassessed in this subsequent focused review.

### C-03 — Resolved: Milestone 0 establishes the minimal package foundation

Original finding (Medium): Requirements: stories L20–59, especially US-31-AC-03 and US-33-AC-03. Design §11 L846–864 starts at Milestone 1, which owns the installable package, CLI, and packaged templates/guidance; §15 L1009–1015 also skips Milestone 0. Consequence: the new first increment cannot meet its exit criteria before some currently later deliverables exist. This is a delivery dependency, not a reason to drop the new criteria.

Original proposed correction: design §11 and §15. Introduce Milestone 0 with contributor setup, CI, and package verification, and identify the minimal package/CLI/resource foundation needed to pass those checks. Keep usable experiment initialization and execution in Milestone 1. Decision needed: does Milestone 0 verify minimal packaged scaffolding (including actual resource files and a functioning CLI smoke invocation), or must it include complete initialization templates and runtime guidance? US-33 does not specify resource completeness or CLI behavior beyond availability; supporting design cannot silently choose the broader scope.

Scoped reconciliation: A focused review at Git revision `361ee6d7cae96c98ce63cf80582bf8a84f64c8cc` confirms that the current user stories settle the Milestone 0 scope decision and the design reflects that delivery boundary. US-33-AC-03 requires at least one provisional template and one provisional runtime guidance file, reserving usable experiment initialization resources for Milestone 1. US-33-AC-06–07 define the minimal `agent-ml --version` CLI and its verification; US-31-AC-03 and US-31-AC-07 cover source-checkout execution and setup verification. Design §8 assigns the minimal CLI, provisional resources, and package verification to Milestone 0. Section 11 now includes Milestone 0 deliverables and exit criteria and explicitly states that Milestone 1 extends that package foundation. Section 15 places the Milestone 0 foundation before experiment-user capabilities. Milestone 0 therefore no longer depends on package capabilities first scheduled for Milestone 1, and no resource-completeness decision remains open for C-03. No user-story or design changes were needed in this reassessment. Implementation and successful verification remain separate work. The original finding, criterion matrix, and counts below remain historical baseline evidence. C-04–C-05 were not reassessed in this focused review.
