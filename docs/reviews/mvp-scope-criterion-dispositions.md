local, scikit-learn experiment workflow. This report proposes dispositions; it

experiment approvals, exact dirty-worktree restoration, cross-framework support,
managed agents and durable recovery. Train-only fitting, data integrity,

## Assistant-supported walkthrough

Developer “make the assistant-support walkthrough explicit”, 2026-11-06,
authorizes this refinement to the proposed scope. **A data scientist using an
external coding assistant is a required MVP acceptance scenario.** The scientist
owns the session and directs the work; the assistant edits experiment-project
files, invokes installed public toolkit interfaces and native DVC stages, and
inspects recorded MLflow results. The scientist chooses the task, target, metric,
data and search bounds. No toolkit-managed agent adapter/session is required.

The following prompts describe intended interactions, not implemented commands or
a currently runnable acceptance demonstration. IP3 must replace proposed command
examples with verified interfaces when available and label remaining proposals.

### Delivery and evidence ownership

- M1: ASW-01–06 for one classification experiment. The proposed first-experiment
  integration story owns the assistant interaction scenario; existing component
  stories retain their technical behavior and test ownership.
- M2: ASW-07–08 extend the scenario to reproduction, notebook/regression and
  customization. The proposed DVC integration story owns replay/cache scenarios;
  relevant notebook/model/component criteria own their corresponding behavior.
- ASW IDs are report-local review references, not new authoritative acceptance
  criterion IDs. IP2-T3 assigns actual criteria and traces every ASW reference;
  IP3-T4 carries the scenario into the design walkthrough and coverage mapping.
- Before MVP acceptance, demonstrate the walkthrough with at least one concrete
  external coding-assistant product/interface/version. Record scientist prompts,
  consequential actions, code/configuration revisions, commands and outcomes,
  MLflow run/artifact references, DVC identities and reproduction checks. A
  concise evidence log suffices; a complete assistant transcript is not required.
- Automatic tests verify toolkit behavior through installed public interfaces;
  the manual assistant walkthrough verifies that a scientist can discover and
  invoke those interfaces, inspect results and direct a revision. Assistant
  statements alone never establish correct outputs or passing acceptance.
- This demonstrates one recorded integration mode, not support for every
  assistant product, authenticated session control or OS-enforced restrictions.
  Managed delegation, autonomous loops and assistant usage accounting stay deferred.
